# LinkedIn Operation Acceptance Checklist

Use only the checks relevant to the requested operation. Every relevant answer must be **YES** before reporting completion.

- [ ] Is the artifact type explicit: text post, image post, carousel, comment, message, connection, profile action, or application upload?
- [ ] For content creation, did the topic come through an active planning handoff with source quality, freshness, duplicate, positioning-pillar, and approval checks, rather than from an unconsumed intelligence/RSS item?
- [ ] Is the approved lane available and authenticated as Ahmed, with no cookie extraction, editing, replay, or repair?
- [ ] Was one suitable LinkedIn tab reused where possible, and is the exact target URL or immutable LinkedIn identity verified?
- [ ] For any write action, did Ahmed explicitly approve the exact text, target, media, file, or connection action?
- [ ] If media or a file was required, does the visible LinkedIn UI show the exact intended asset before submission or publishing?
- [ ] Does fresh visible LinkedIn evidence show the final published, sent, connected, or submitted state on the correct account and target?
- [ ] Are reported totals deduplicated by activity URN, post URL, job ID, or other immutable identity rather than retries?
- [ ] Are analytics claims backed by author-visible analytics, with unavailable metrics marked `blocked-login` rather than inferred from public reactions?
